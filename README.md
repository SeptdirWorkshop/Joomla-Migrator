# Joomla Migrator

Системный плагин Joomla для переноса категорий, материалов и тегов из базы данных сайта-донора в текущий сайт через Joomla CLI.

## Возможности

Плагин позволяет:

- подключиться к базе данных сайта-донора;
- экспортировать данные Joomla в промежуточные JSON-файлы;
- импортировать данные в текущий сайт через штатные модели Joomla;
- запускать полный перенос или отдельные этапы;
- удалить созданные мигратором JSON-файлы.

Сейчас поддерживаются:

- категории материалов `com_content`;
- материалы `com_content`;
- теги `com_tags`;
- связи материалов с тегами.

## Схема работы

```text
База данных донора
        │
        │ migrator:export:*
        ▼
administrator/migrator/*.json
        │
        │ migrator:import:*
        ▼
База данных текущего сайта
```

Экспорт читает базу данных донора, указанную в параметрах плагина, но сохраняет JSON-файлы на сайте-получателе.

Импорт читает эти файлы и записывает данные в базу данных текущего сайта.

Устанавливать плагин на сайт-донор не требуется, если его база данных доступна сайту-получателю.

## Требования

Для работы необходимы:

- установленный и включённый плагин `System - Joomla Migrator`;
- рабочая Joomla CLI;
- PHP CLI;
- доступ к базе данных сайта-донора;
- права на запись в каталог `administrator`;
- резервная копия базы данных сайта-получателя.

Минимальные версии Joomla и PHP пока явно не зафиксированы в манифесте расширения. Текущая среда разработки использует Joomla 6.1 и PHP 8.3.

## Установка

Установите собранный пакет расширения через административную панель Joomla:

```text
System → Install → Extensions
```

После установки плагин включается автоматически.

Проверьте его состояние в разделе:

```text
System → Manage → Plugins
```

## Настройка базы данных донора

Откройте параметры плагина `System - Joomla Migrator` и укажите подключение к базе данных сайта-донора.

| Параметр | Обязательный | Описание |
|---|---:|---|
| Тип базы данных | Нет | Если не указан, используется тип подключения сайта-получателя |
| Хост | Нет | Если не указан, используется хост сайта-получателя |
| Пользователь | Нет | Если не указан, используется пользователь сайта-получателя |
| Пароль | Нет | Если не указан, используется пароль сайта-получателя |
| Имя базы данных | Да | Имя базы данных сайта-донора |
| Префикс таблиц | Нет | Если не указан, используется префикс сайта-получателя |

Если донор находится на том же сервере и использует те же реквизиты подключения, обычно достаточно указать имя его базы данных и префикс таблиц.

Не публикуйте реквизиты базы данных в репозитории, логах или диагностических материалах.

## JSON-файлы

Промежуточные данные сохраняются в каталоге:

```text
JPATH_ROOT/administrator/migrator
```

Создаются следующие файлы:

```text
com_content.categories.json
com_content.articles.json
com_tags.tags.json
```

Повторный экспорт соответствующего типа данных заменяет существующий JSON-файл.

## Использование CLI

Команды необходимо запускать из корневого каталога Joomla:

```bash
php cli/joomla.php <command>
```

Проверить регистрацию команд можно через список Joomla CLI:

```bash
php cli/joomla.php list migrator
```

### Полный экспорт

Экспортирует категории, материалы и теги:

```bash
php cli/joomla.php migrator:export:joomla
```

Этапы экспорта выполняются в следующем порядке:

1. категории материалов;
2. материалы;
3. теги.

### Полный импорт

Импортирует категории, теги и материалы:

```bash
php cli/joomla.php migrator:import:joomla
```

Этапы импорта выполняются в следующем порядке:

1. категории материалов;
2. теги;
3. материалы.

Порядок важен: при импорте материалов уже должны существовать соответствующие категории и теги.

### Отдельные команды

| Команда | Назначение |
|---|---|
| `migrator:export:content:categories` | Экспорт категорий материалов |
| `migrator:export:content:articles` | Экспорт материалов |
| `migrator:export:tags` | Экспорт тегов |
| `migrator:import:content:categories` | Импорт категорий материалов |
| `migrator:import:content:articles` | Импорт материалов |
| `migrator:import:tags` | Импорт тегов |
| `migrator:clean` | Удаление каталога с JSON-файлами |

Пример экспорта только категорий:

```bash
php cli/joomla.php migrator:export:content:categories
```

Пример импорта только тегов:

```bash
php cli/joomla.php migrator:import:tags
```

## Рекомендуемый порядок миграции

1. Создайте резервную копию базы данных сайта-получателя.
2. Настройте подключение к базе данных донора.
3. Выполните экспорт.
4. Проверьте наличие и содержимое JSON-файлов.
5. Импортируйте категории.
6. Импортируйте теги.
7. Импортируйте материалы.
8. Проверьте результат в административной панели и на сайте.
9. После успешной проверки удалите промежуточные файлы.

```bash
php cli/joomla.php migrator:export:joomla
php cli/joomla.php migrator:import:joomla
php cli/joomla.php migrator:clean
```

Не запускайте `migrator:clean` до завершения импорта: команда удаляет весь каталог `administrator/migrator`.

## Повторный импорт

Исходные числовые идентификаторы объектов не сохраняются.

Для поиска существующих записей используются:

- категория — `extension` и `path`;
- тег — `path`;
- материал — `alias` и идентификатор сопоставленной категории.

Если соответствующая запись найдена, модель Joomla получает её идентификатор и обновляет запись. Если запись не найдена, создаётся новая.

Категории и теги сопоставляются по путям, поэтому их иерархия должна экспортироваться и импортироваться целиком.

## Ограничения

В текущей реализации:

- поддерживаются только категории материалов, материалы и теги Joomla;
- файлы изображений и другие медиафайлы не копируются;
- пользовательские поля не переносятся;
- пользователи и авторы материалов не сопоставляются;
- версии материалов и история изменений не переносятся;
- связи многоязычных материалов не переносятся;
- уровни доступа копируются как числовые идентификаторы и отдельно не сопоставляются;
- импорт не является транзакционным — ошибка может оставить частично импортированные данные;
- режима предварительного просмотра или `dry-run` нет;
- ошибки выводятся в консоль, но обработанная ошибка сейчас не гарантирует ненулевой exit code.

Импорт материалов пока не готов для производственного использования: в `importContentArticles()` остаётся отладочная остановка после первого материала, а перед сохранением модели статьи необходимо корректно инициализировать компонентный контекст CLI.
